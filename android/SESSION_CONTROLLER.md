## Reducer inputs and outputs

SessionController.reduce receives the current SessionSnapshot, optional named
graph event, monotonic timestamp in milliseconds, explicit SessionControls,
optional RecoveryContext and expected ordinary-input sequence.

SessionControls are adjudicated decisions supplied by other services, not
inferences about a child's emotions. The priority is fatal integrity, safety
stop, child stop, child pause, protocol abort, technical interruption, then the
ordinary graph event. Global fatal/stop/abort controls can end any nonterminal
session. Pause and technical interruption still require a supported graph edge.
An unsupported higher-priority action is rejected rather than replaced by a
lower-priority action. Terminal states cannot reopen.

The decision contains either an unchanged snapshot and rejection code, or a
new snapshot and SessionTransition. Each accepted transition has an incremented
sequence, timestamp, from/to states, reason, graph configuration hash and
available recovery-context hash. Timestamps can be equal within a clock tick
but cannot move backward. No timestamp or identifier is fabricated by the
reducer. EngineeringJournalRuntime uses SystemClock.elapsedRealtime for developer inputs.

Ordinary stale callbacks are rejected. Genuine global control requests act on
the current snapshot even when their rendered sequence is old. Callers must
serialize reducer application and side effects; the Android explorer uses the
single background IO executor, publishing committed state on the main thread.
The journal persists inputs and verifies reducer replay. The reducer does not itself prove that a
service event such as event_persisted is true.

## Recovery-context lock

Entry to RECOVERY_MONITORING requires six explicit fields:

| Field | Kotlin type |
| --- | --- |
| task rule ID | String |
| cognitive difficulty | nonnegative Int |
| sensory load | nonnegative Int |
| response window, milliseconds | positive Int |
| stimulus distribution/content ID | String |
| cue condition | String |

The lock is retained through pause, interruption and recovery closure. Observed
and censored outcomes require the caller to confirm exactly the locked context.
A changed or missing context rejects those outcomes. Explicit
measurement_context_changed or required_data_invalid closes the event as
RECOVERY_DATA_INVALID rather than censoring. Context hashes use length-prefixed
UTF-8 fields and SHA-256, with no locale-dependent numeric representation.

Resume requires the explicit stored source state. Recovery resume additionally
requires the original verified context. A technical interruption can take the
graph's recovery_invalidated path only when a recovery context exists.
A child-paused recovery cannot bypass the canonical graph: restore/verify its
locked context before resume, or stop. Qualification of time continuity and
handling of a compromised pause belong to the future recovery service.

The reducer does not calculate a score or stability window. An explicit
criterion_stable input is a service assertion, not validation of that assertion.
Persistence acknowledgement is required by the graph before return to the goal.

## Active-control boundary

SessionMode.ACTIVE_CONTROL permits onboarding, calibration, baseline, pause,
interruption, reflection and completion. It blocks entry to challenge,
regulation and recovery states. This enforces the core study boundary without
inventing the task or pacing policy for the final active-control intervention.

## Developer explorer

The explorer provides simulated graph-event buttons and a synthetic context
marked engineering-demo-only. It displays state, sequence, resume target and
rejection/transition reasons. Pause and stop stay outside the scrolling list.
Backgrounding enters TECHNICAL_INTERRUPT where supported, otherwise child
pause where supported. Resumption always requires an explicit action. Activity
recreation restores the verified journal. Process restart requires explicit
interruption handling, while a changed clock domain permits inspection only.
See [PERSISTENCE.md](PERSISTENCE.md). The primary timed Signal Gate now drives
the canonical Core transitions. Its short engineering rule-switch path still
cannot silently become a recovery outcome: without the required mapping-matched
target-rule reference, recovery is explicitly recorded as data-invalid.

censored paths, invalid data/context changes, explicit resume, control priority,
terminal stop, persistence failure, stale events, clock ordering, challenge
suppression, active-control exclusion and deterministic replay/context hashes.

From app/mobile-android-kotlin:

    gradle :app:testCoreDebugUnitTest :app:assembleCoreDebug

interruption during baseline and recovery, explicit resume, pause/stop on a
small screen and large font scaling. These device checks remain unverified.

frozen participant records, qualification, timed task/calibration, eligibility,
scoring, recovery validity and cue execution. Estimated 2–4

additional work.
